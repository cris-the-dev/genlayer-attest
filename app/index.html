How it works

Ownership first. Then the claim. Then it stays honest.

A profile anyone can type is worth nothing. Attest only signs what a public source both belongs to you and supports.

  1. Tag your source

    Add genlayer-attest:<your address> to a .genlayer-attest file in your repo, /.well-known/ on your domain, or your page.

    github_repodomainweb
  2. Validators check it

    Code confirms the tag is there. Then independent validators each read the source and must agree it supports your statement, down to the hash of the bytes they read.

  3. Anyone can recheck

    Delete the tag or change the source so it no longer backs you, and anyone can revoke it with a recheck. Attestations also expire on their own.

Use cases

Gate on facts, not on self-declared profiles.

Every case below is one view call from another contract.

Grants and bounties

Pay out only to the address that really maintains the repo it is funding.

is_attested_subject(a, "github_repo", repo)
Allowlists

Let a protocol or DAO admit members who control a named domain.

is_attested(a, "domain")
Hiring and reputation

Back a claimed role or track record with the page that states it.

is_attested(a, "web")
Anti-impersonation

Show a verified badge only for wallets proven to own the official site.

is_attested_subject(a, "domain", site)

For developers

One line in your contract.

Attest is a public GenLayer contract. Read it from your own intelligent contract, or from any frontend with genlayer-js.

your_contract.pyGenVM
# only verified maintainers can claim the grant
attest = gl.get_contract_at(Address(ATTEST))
if not attest.view().is_attested_subject(
        gl.message.sender_address.as_hex,
        "github_repo", "acme/widget"):
    raise gl.vm.UserError("not a verified maintainer")

Why trust it

Built so a dishonest leader gets nowhere.

GenLayer picks one validator to lead each check; the others redo it independently.

Ownership is checked in code

Repo existence, the tag and the domain file are verified deterministically. The model is only asked whether the source supports the claim.

Validators re-derive everything

Verdict, reason code and source hash must match each validator's own result. A forged hash or note is rejected.

Outages never revoke

A timeout, rate limit or 5xx reverts the check instead. Only a missing tag or an unsupported claim revokes.

Injection-resistant

The statement and the source are fenced and treated as data, never as instructions.
